# Запрос администратору сервера

Боевой машиной `cheerful-gardener` занимается отдельная сессия coding agent в
`E:\projects\infra`. Она выдаёт порты и поддомены, считает ресурсы, ставит вхосты
и сертификаты и ведёт учёт. Машина маленькая (1 vCPU, ~2 ГБ на всех), поэтому её
ресурсы распределяет она одна.

## Что делать самому, а что — через администратора

**Через администратора** — всё, что меняет размещение:

- новое приложение, новая служба, стенд;
- порт, поддомен, вхост, маршрут nginx, сертификат;
- `docker-compose.yml` на сервере: лимиты памяти, тома, сети, состав служб;
- таймеры, бэкапы, каталоги на машине, места для секретов;
- всё, что может задеть соседей: рост памяти или диска, тяжёлые фоновые задачи.

**Самому можно:**

- читать учёт — `E:\projects\infra\servers\cheerful-gardener.md`,
  `E:\projects\infra\apps\<приложение>.md`;
- обычный передеплой уже принятого приложения его собственной командой из
  `apps/<приложение>.md`, если меняется только код, а размещение не меняется;
- осматривать машину по SSH только на чтение.

Порт «наугад», правка вхоста руками и запись на машину мимо деплоя запрещены.

## 1. Подготовить запрос

1. Прочитать `E:\projects\infra\docs\requests.md` и заполнить образец: службы с
   памятью и лимитом, хранилище, бэкапы, маршруты, имена секретов, команда деплоя.
   Без чисел запрос не примут.
2. Закоммитить в своём репозитории то, что администратор будет разворачивать:
   деплоится закоммиченный `HEAD`.
3. Сохранить готовый запрос в `tmp/hosting-request.md` текущего проекта и показать
   его инженеру. В первой строке указать путь к репозиторию и, если доступно,
   имя текущей сессии.

## 2A. Передать запрос из OpenCode

OpenCode V2 не имеет эквивалента Claude `ListAgents`/`SendMessage` для живой
передачи сообщения в сессию другого проекта. Не имитировать отправку и не запускать
деплой через `opencode run` без явного разрешения инженера.

Остановиться на подготовленном запросе и попросить инженера:

```
cd E:\projects\infra
opencode
```

В новой сессии администратора инженер передаёт содержимое `tmp/hosting-request.md`.
После его ответа продолжить работу в исходном проекте. До ответа не выполнять
серверные изменения самому.

## 2B. Передать запрос из Claude Code

1. Найти сессию администратора через `ListAgents` (при необходимости загрузить
   `ListAgents` и `SendMessage` через `ToolSearch`). Нужна сессия `infra-*`;
   строка `This session is …` обозначает текущую, а не целевую сессию.
2. Отправить запрос через `SendMessage({ to: "<имя infra-сессии>", message: "<запрос>" })`.
   В первой строке указать имя своей сессии и путь к репозиторию.
3. Ждать ответа, не опрашивая сессию. Если найдено несколько `infra-*`, выбрать
   `idle`, а при сомнении спросить инженера.

## Если сессии администратора нет

Не делать работу на сервере вместо неё. Подготовленный запрос уже находится в
`tmp/hosting-request.md`; попросить инженера запустить администратора в
`E:\projects\infra` через `opencode` или `claude`, соответственно используемому
harness, и затем продолжить текущую задачу.
