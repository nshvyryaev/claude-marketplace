# acceptance

Критерии приёмки как первоклассный артефакт: жизненный цикл, хук, делающий их
неизменяемыми во время реализации, и правила о том, когда нужно подтверждение
инженера.

Плагин везёт движок и хук; проект владеет только своими критериями в
`docs/acceptance/`.

## Зачем

Самый дорогой отказ — агент, отчитавшийся «готово», когда результат расходится
с заданием. Правило в промпте этого не ловит: подгонка критерия под результат
выглядит как уточнение формулировки и проходит незамеченной в общем диффе.

Поэтому критерии заперты хуком: черновик правится свободно, всё остальное —
только через явную разморозку с записью причины в журнал.

## Файл критериев

`docs/acceptance/<slug>.md`:

```markdown
---
slug: move-reject
kind: feature
status: draft
title: "Отказ хода объясняет причину"
---

## Критерии

- [scenario] Ход с двумя изменёнными буквами отклонён, показана причина,
  введённые буквы остаются на месте
- [visual] Экран отказа не использует красный цвет и не сдвигает раскладку
- [check] npm run typecheck выходит с нулём
```

Способы проверки: `scenario` (машина), `snapshot` (пиксельный диф, только
регрессия), `visual` (осмотр агентом), `check` (команда с кодом возврата).

## Жизненный цикл

```
draft → approved → frozen → verified
             ↑                  │
             └──── unfreeze ────┘  (с причиной, в журнал)
```

| Статус | Что означает | Файл правится |
|---|---|---|
| `draft` | критерии пишутся | да |
| `approved` | инженер подтвердил | **нет** |
| `frozen` | взято в работу | **нет** |
| `verified` | доказано | **нет** |

## Когда нужно подтверждение

`feature` и `ui` — да. `bug`, `chore`, `data` — нет, но у каждого свой
обязательный критерий: воспроизведение, неизменность поведения, проверка
конвейера соответственно.

## Команды

```
acceptance new <slug> --kind <feature|ui|bug|chore|data> --title "..."
acceptance list
acceptance show <slug>
acceptance lint <slug>
acceptance approve <slug> --evidence "ответ инженера дословно"
acceptance freeze <slug>
acceptance unfreeze <slug> --reason "почему критерий меняется"
acceptance verified <slug> --evidence "чем доказано"
```

Корень проекта берётся из `CLAUDE_PROJECT_DIR`, иначе — текущий каталог.

## Хук

`PreToolUse` на `Edit|Write|MultiEdit|NotebookEdit`. Запрещает правку файлов в
`docs/acceptance/`, чей статус не `draft`. Создание нового файла разрешено —
это новый черновик.

Хук никогда не валит работу из-за собственной поломки: любая неожиданность
означает «нет мнения». Единственное исключение — файл, который не удалось
разобрать, но в котором виден запертый статус: тут молчать опаснее.

## Чего это не гарантирует

`[visual]` — это агент, оценивающий собственную работу. `--evidence` заполняет
тоже он. Механика делает подделку **видимой** в git и в журнале, а не
невозможной.

Контур ловит подгонку критериев и забытые проверки. Добросовестное заблуждение
он не ловит — для этого нужен независимый судья, который не видел, как писался
код.
